# IAMU 动态泊位—岸桥有限改约预算原型 v0.1（中文使用说明）

## 定位

该代码是一个**新的动态信息/计划承诺仿真外层**，不需要重训 ERL-DDE。它可以选择从原始已训练 ERL-DDE 模型中**读取冻结推理产生的船舶顺序、泊位位置建议**，再交给新增的动态计划与执行层进行可行化。它**不是**原论文 C++ 环境本身的动态版，也**没有**接入岸电或真实减排指标。这些差异在论文里必须讲清楚。

## 安装与最简运行

在服务器新建一个目录，避免影响正在训练的原始文件：

```bash
cd ~/code/iamu
mkdir -p IAMU_dynamic
cd IAMU_dynamic
# 将下载的 zip 放到此目录并执行 unzip iamu_dynamic_commitment_v0.1.zip
python run_experiment.py --demo --scenario shock --budgets 0,2,5
python -m unittest discover -s tests -v
```

## 基于作者 case_code 原始案例运行（不需要 PyTorch）

```bash
python run_experiment.py \
    --case ../2024LiERLDDE/case_code/0.txt \
    --scenario repeated --seed 42 --updates 2 \
    --policies no_replan,threshold,budget_aware \
    --budgets 0,2,5,unlimited \
    --out results/case0_demo
```

核心对比输出：`results/case0_demo/comparison.csv`。其中 `weighted_wait` 越低越好，`spent` 是**累计实际发布修改次数**；`total_operational_slip` 是运营实际偏离发布开始时间的幅度，不计入改约预算。所有基线使用**相同** ETA 更新序列和相同隐藏实际到港时间。

## 基于已经训练好的 ERL-DDE 权重，无需重训

此模式需要：Linux 的 g++、Python、numpy、torch、`../2024LiERLDDE/model.py` 和 `../2024LiERLDDE/BACAP_env.cpp`，以及**已有的完整保存权重**。

```bash
mkdir -p checkpoints
# 用你服务器上已经存在、且不会被运行中训练覆盖的真实路径替换源文件
cp ../2024LiERLDDE/BACAP_checkpoints/2/synced_model_0_55906.pth \
    checkpoints/frozen_es_0.pth

python run_experiment.py \
    --case ../2024LiERLDDE/case_code/0.txt \
    --backend erldde \
    --erldde-root ../2024LiERLDDE \
    --checkpoint checkpoints/frozen_es_0.pth \
    --build-probe \
    --scenario shock --updates 1 --seed 42 \
    --policies no_replan,budget_aware --budgets 0,2,5 \
    --out results/case0_erldde_frozen
```

过程不会调用 `main.py`、`train_loop()` 或优化器，不会改变任何已有模型权重；只是使用原始 ES 做预测。单独编译一个 `libBACAP_env_probe.so`，不会覆盖作者原来的共享库。

本模式的作用限定于**提供候选排序和泊位位置偏好**，整个未来计划的维护、预算约束和真实运行仍由新的仿真框架执行。不要把它标注为“原始 ERL-DDE 在动态环境上的直接训练结果”。

注意：这里已测试了独立 C++ 接口模拟桩，但未使用你的真实 C++ 源码+正式权重完成验证。若真实适配运行出现异常，请保留完整栈信息与 `probe_build` 的编译日志。

## 可直接做的实验矩阵

- ETA 类型：`small`、`repeated`、`shock`
- 随机种子：建议至少 10 个，且相同种子在所有方法、预算设置之间配对
- 全局预算：`0,2,5,10,unlimited`
- 决策基线：`no_replan`、`always`、`threshold`、`periodic`（当前版本为事件触发且满足最小间隔的周期门控）、`budget_aware`
- 正式实验还需要：不同 `case_code` 测试实例、权重快照版本、不同更新频次与幅度、更多限制和验证

当前结果只是**可运行原型的工程验证**，不能直接作为期刊论文中成熟算法的优越性证据。
